# Token Stats для OpenCode Desktop

Плагин боковой панели OpenCode 2 Desktop: показывает, сколько токенов потребила каждая
модель, по всем сессиям на этой машине.

Колонки: модель, сообщения, вход, выход, рассуждения, чтение кэша, запись кэша, всего,
цена. Под таблицей — строка ИТОГО и «свежие» (вход + выход + рассуждения). Фильтры: всё
время, сегодня, 7 дней и, опционально, только каталог текущей сессии.

English: [README.md](README.md).

## Требования

- OpenCode Desktop 2.3.x. GUI-API плагинов экспериментальный и может меняться между
  релизами.
- Node.js 20+ — только если собираете плагин сами; в репозитории уже лежит собранный
  `dist/gui-experimental.cjs`.

## Установка из git (рекомендуется)

```bash
git clone https://github.com/edwardgra4ev/opencode-token-stats-gui-plugin \
  ~/.config/opencode/plugins/token-stats
```

Добавьте плагин в `~/.config/opencode/opencode.json`:

```jsonc
{
  "plugins": ["./plugins/token-stats"],
}
```

Один раз перезапустите OpenCode Desktop. Панель появится в меню `+` боковой области, в
палитре команд и по `/tokens`.

## Установка из архива релиза

1. Скачайте `opencode-token-stats-gui-plugin-vX.Y.Z.zip` из
   [Releases](https://github.com/edwardgra4ev/opencode-token-stats-gui-plugin/releases).
2. Распакуйте в `~/.config/opencode/plugins/token-stats`.
3. Добавьте `"./plugins/token-stats"` в `plugins` в `~/.config/opencode/opencode.json`.
4. Перезапустите Desktop.

В архиве уже есть `dist/gui-experimental.cjs`; собирать ничего не нужно.

## Установка из другого каталога

Плагин грузится из любого каталога — укажите его путь в `plugins` (абсолютный или
относительно каталога конфигурации):

```jsonc
{
  "plugins": ["/mnt/hdd/Dev/linux/token-stats-gui-plugin"],
}
```

## Расположение базы

Плагин ищет `opencode.db` там, где OpenCode хранит свои данные:

| ОС | Путь |
| --- | --- |
| Linux | `$XDG_DATA_HOME/opencode/opencode.db`, по умолчанию `~/.local/share/opencode/opencode.db` |
| macOS | `~/Library/Application Support/opencode/opencode.db` |
| Windows | `%APPDATA%\opencode\opencode.db` |

Сборки по каналам (`opencode-dev.db`, `opencode-beta.db`, …) подхватываются автоматически,
если `opencode.db` нет. Найденный путь показывается под таблицей и в баннере ошибки.

Чтобы указать другой файл, задайте опцию `db` (абсолютный путь, `~/…` или путь относительно
каталога данных выше):

```jsonc
{
  "plugins": [
    {
      "package": "./plugins/token-stats",
      "options": { "db": "~/backups/opencode.db" }
    }
  ],
}
```

Работает и та же переменная, что использует сам OpenCode: `OPENCODE_DB`. Приоритет: опция
плагина, затем `OPENCODE_DB`, затем путь по умолчанию для платформы.

## Использование

- Откройте боковую панель, нажмите `+` и выберите **Tokens**; или выполните `/tokens`;
  или найдите команду в палитре.
- Выберите период и, при необходимости, **Этот проект** — тогда считаются только сессии
  из каталога текущей сессии.
- Клик по заголовку колонки сортирует по ней, повторный — в обратном порядке; колонка
  модели сортируется по алфавиту, числа при первом клике — по убыванию.
- Поле **Поиск по моделям** фильтрует строки по `provider/model`; ИТОГО и «свежие»
  считаются по видимым строкам.
- **Обновить** перечитывает базу; автообновления нет.

## Обновление

```bash
git -C ~/.config/opencode/plugins/token-stats pull
```

Затем перезапустите Desktop (или перезагрузите плагины в приложении). Релизы помечаются
тегом `vX.Y.Z`, изменения — в [CHANGELOG.md](CHANGELOG.md).

## Как считаются цифры

- Источник: каталог данных OpenCode, таблица `session_message`, строки
  `type = 'assistant'` (см. [Расположение базы](#расположение-базы)).
- Бакеты токенов — из поля `tokens` сообщения: `input`, `output`, `reasoning`,
  `cache.read`, `cache.write`; цена — из `cost`.
- `total = вход + выход + рассуждения + чтение кэша + запись кэша`.
- «Свежие» — `вход + выход + рассуждения`, то есть часть, не пришедшая из кэша промпта.
- Строки сортируются по `вход + выход + чтение кэша` — как в эталонном агрегаторе
  `opencode-token-stats.py`. Итоги, «свежие» и порядок строк сверены с ним на снапшоте
  реальной базы.
- База открывается только на чтение на каждый запрос; режим WAL позволяет читать её во
  время работы OpenCode.

На бесплатных и подписочных провайдерах цена `0,00`. Незавершённое сообщение ассистента
считается сообщением с нулевыми токенами. Учитываются только эта машина и этот профиль.

## Разработка

```bash
npm install
npm run typecheck
npm run build     # dist/gui-experimental.cjs, лежит в репозитории
npm run watch     # пересборка при изменении; панель перезагружается во всех окнах
```

`dist/` хранится в репозитории, чтобы обычный `git clone` не требовал сборки. CI
пересобирает бандл и падает, если он отличается от закоммиченного.

Структура:

| Путь | Назначение |
| --- | --- |
| `src/index.ts` | серверная часть: `Plugin.define({ id: "token-stats" })`, регистрация RPC |
| `src/rpc.ts` | RPC-контракт `stats`, общий для обеих частей |
| `src/stats.ts` | чтение SQLite и агрегация |
| `src/gui.tsx` | вход GUI: панель, пункт меню, команда `/tokens`, стили |
| `src/gui/panel.tsx` | Solid-компонент таблицы |
| `src/gui/definition.ts`, `src/gui/i18n.ts` | декларации, тексты en/ru |

Релиз: поднимите `version` в `package.json`, добавьте запись в `CHANGELOG.md`, поставьте
тег `vX.Y.Z` и запушьте его. Workflow релиза сверяет тег с `package.json`, пересобирает
плагин и прикладывает архив.
